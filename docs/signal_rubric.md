# 信号尽调 Rubric（Signal Due-Diligence Rubric）

> **本文件由 `src/validation/rubric.py` 的常量自动生成（`python -m src.validation.rubric`）。请勿手工编辑；改判据请改常量后重新生成。**

结果侧验证（`checklist.py` / `gate.py` / `significance.py` …）问的是「你按规矩测量了吗」；本 rubric 问的是「这件事在机制上值得信吗」。两者互补：先过 rubric，再花评估预算。

## 评分与分档

每维只允许 **1 / 3 / 5** 分（不允许 2/4 分——中间必须是一个明确承诺，不是和稀泥）。
加权总分 = 各维分数×权重 之和 / 权重之和（对已作答维度）。

| 分档 | 条件 | 含义 |
|---|---|---|
| `ALLOW_EVALUATION` | 加权总分 ≥ 3.5 | 允许进入评估预算 |
| `NEEDS_STRENGTHENING` | 2.5 ≤ 加权总分 < 3.5 | 需补强特定维度 |
| `REJECT` | 加权总分 < 2.5 | 拒绝（除非用户明确要求强行评估，需在登记簿记录 user_override） |

## 权重

权重写在 `rubric.py::DIMENSION_WEIGHTS` 常量里，供未来 rubric search 迭代。默认权重：

| # | 维度 | 权重 |
|---|---|---|
| 1 | 对手方与套利壁垒（`counterparty_arbitrage`） | 2 |
| 2 | 机制可陈述性（`mechanism_stateability`） | 1 |
| 3 | 基率锚定（`base_rate_anchoring`） | 1 |
| 4 | 容量与成本现实（`capacity_cost_reality`） | 1 |
| 5 | regime 依赖声明（`regime_dependency_declared`） | 1 |
| 6 | 衰减逻辑与监控（`decay_logic_monitoring`） | 1 |
| 7 | 数据护城河（`data_moat`） | 1 |
| 8 | 是否需要预测不可预测之物（`no_chaos_prediction`） | 1 |
| 9 | 可执行性（`executability`） | 1 |
| 10 | 事前注册状态（`preregistration`） | 2 |

**对手方与套利壁垒**、**事前注册状态** 默认加倍权重 —— 这两个问题的缺席烧掉了我们最多的评估预算。

## 十维判据

### 1. 对手方与套利壁垒 — `counterparty_arbitrage`（权重 2）

**问题**：谁在另一边？为什么这个价差/错价不被套利掉？为什么现在还存在？

| 分值 | 判据 |
|---|---|
| **5** | 能明确指出对手方（如被动对冲者、被迫再平衡的结构性资金、受监管/受托限制无法套利的机构），并说清错价为何持续、为何不会被迅速套利掉；有结构性/行为性溢价的证据。 |
| **3** | 能说出大致的对手方，但对『为何不被套利』只有一般性论述（风险大、流动性差），没有具体壁垒或证据。 |
| **1** | 从未问过对手方是谁；默认 edge 源于『市场没发现』或『统计显著』，没有解释它为何持续存在。 |

### 2. 机制可陈述性 — `mechanism_stateability`（权重 1）

**问题**：能否一句话说清因果链（不靠『统计上显著』来替代机制）？

| 分值 | 判据 |
|---|---|
| **5** | 一句话即可陈述完整因果链（A→B→价格），且不依赖『统计显著』作为替代；能指出链条中哪个环节会失效。 |
| **3** | 有因果故事但存在跳跃或未验证的中介环节，需要数据确认才能成立。 |
| **1** | 只有『因子 X 与收益 Y 相关 / 回测好』；没有机制，或机制是看结果之后补编的故事。 |

### 3. 基率锚定 — `base_rate_anchoring`（权重 1）

**问题**：无条件基率是多少？宣称的 edge 是与正确的零假设比吗？

| 分值 | 判据 |
|---|---|
| **5** | 明确给出无条件基率（事件频率 × 无条件收益），并说明 edge 相对正确零假设的增量；已扣除基率。 |
| **3** | 提到基率但未量化，或比较的零假设并非正确基准（与 0 比而非与买入持有 / 动量基线比）。 |
| **1** | 只看条件收益率，从未问『不触发时会发生什么』；把市场 beta / 无条件漂移当成 alpha。 |

### 4. 容量与成本现实 — `capacity_cost_reality`（权重 1）

**问题**：在真实成本/税/滑点/你的资金规模下是否还活着？

| 分值 | 判据 |
|---|---|
| **5** | 用真实成本/税/滑点/借券费/涨跌幅限制以及自己实际资金规模做过净额检验，且容量远大于资金量。 |
| **3** | 做了成本敏感性但参数乐观（只用零成本或单一成本），或容量未被评估。 |
| **1** | 收益是毛收益，没有成本/税/滑点假设，或假设明显不可实现（如按开盘无滑点成交）。 |

### 5. regime 依赖声明 — `regime_dependency_declared`（权重 1）

**问题**：应该在什么市场环境下有效，这个声明是事前写的吗？

| 分值 | 判据 |
|---|---|
| **5** | 事前（注册时）写明有效/失效的市场环境与机械判据，并在多个 regime 子样本中检验过。 |
| **3** | 事前未写，事后描述了 regime 依赖；或声明模糊、无法机械判定。 |
| **1** | 从未声明 regime 依赖，默认策略在所有环境下有效——通常等于对某一段行情过拟合。 |

### 6. 衰减逻辑与监控 — `decay_logic_monitoring`（权重 1）

**问题**：什么会侵蚀这个 edge？有没有对应的监控指标？

| 分值 | 判据 |
|---|---|
| **5** | 明确指出什么会侵蚀 edge（拥挤/制度变化/数据修正/竞争者），并有可部署的监控指标与降级红线。 |
| **3** | 能说出衰减来源但没有监控指标，或只有定性描述。 |
| **1** | 假设 edge 永久有效；没有任何衰减假设或监控安排。 |

### 7. 数据护城河 — `data_moat`（权重 1）

**问题**：数据是独占/新鲜的，还是人人都有的（拥挤风险）？

| 分值 | 判据 |
|---|---|
| **5** | 数据独占、需许可证/自采/低延迟，他人难以复制；有清晰的数据护城河。 |
| **3** | 数据半独占（付费可购）或有时效性优势，但并非不可复制。 |
| **1** | 数据人人都有（公开价格/财报/免费 API），信号一旦公开就会被拥挤掉。 |

### 8. 是否需要预测不可预测之物 — `no_chaos_prediction`（权重 1）

**问题**：是否依赖预测混沌资产的方向？

| 分值 | 判据 |
|---|---|
| **5** | 不依赖预测方向；赚的是结构性/机械性/风险溢价的钱（收租、提供流动性、承接再平衡流）。 |
| **3** | 需要方向判断但有限制（只赌均值回归、带保护、条件触发），并非裸赌方向。 |
| **1** | 本质是预测混沌资产（单标的短期方向）的涨跌；edge 等价于『猜得准』。 |

### 9. 可执行性 — `executability`（权重 1）

**问题**：标的真实存在、下单可行、无借券/涨跌幅限制障碍？

| 分值 | 判据 |
|---|---|
| **5** | 标的真实存在、可交易，无借券/涨跌幅/流动性障碍；下单时点与数据可得时点一致。 |
| **3** | 可交易但有摩擦（需要特定券商、部分标的受限、容量/时段受限）。 |
| **1** | 标的不存在/不可交易，或依赖无法成交的价格，或信号收盘后才可得却假设盘中行动（前视）。 |

### 10. 事前注册状态 — `preregistration`（权重 2）

**问题**：假设在看数据之前就写下来了吗？

| 分值 | 判据 |
|---|---|
| **5** | 假设、触发条件、成功判据在查看相关数据之前已写入登记簿（带 UTC 时间戳与 commit），事后未修改。 |
| **3** | 事前写了部分条件，但关键判据或阈值是看过数据之后补上的。 |
| **1** | 完全事后提出；由已经看到的回测结果倒推假设、窗口、阈值（典型的多重比较 / HARKing）。 |

## 用法

```python
from src.validation.rubric import score

res = score({
    "counterparty_arbitrage": 1,
    "mechanism_stateability": 3,
    ...  # 10 维全部作答
})
assert res.band in {"ALLOW_EVALUATION", "NEEDS_STRENGTHENING", "REJECT"}
```
